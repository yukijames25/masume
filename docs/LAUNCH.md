## 本文

### Excel方眼紙は、AIにとって読みにくく、書くのはもっと難しい

役所や社内の申請書には、いわゆる「Excel方眼紙」で作られたものがまだたくさんあります。列幅を細かくそろえ、セルを結合して罫線を引いた、あの様式です。

生成AIに読ませるためのツール（MarkItDown など）は増えました。それでも、AIに**書かせる**となると話は別です。

- 汎用のExcel操作ツールは、セル番地で指定しないと書けない。方眼紙では「氏名の欄がどこか」をAIが外しやすい
- ライブラリで保存し直すと、図形・画像・印影・一部の書式が落ちることがある
- 「令和　年　月　日」「□有　□無」「〒　　－」といった日本の様式の書き方を、誰も扱っていない

### masume（升目）がすること

```
$ masume inspect 休暇届.xlsx
休暇届!T5:AG5    日付(セル内)  日付
休暇届!H9:AG9    テキスト      [申請者] 氏名
休暇届!H12:AG12  選択          [休暇内容] 休暇の種類  選択肢=年次有給休暇/特別休暇/代休/その他
...
$ masume fill 休暇届.xlsx values.json -o 休暇届_記入済.xlsx
```

- **テンプレートは無加工**：結合セル・罫線・太字見出しから「ラベル → 入力欄」を推定します
- **壊さない**：シートXMLの該当セルだけを差し替えます。ほかの部品はバイト単位で同一です
- **日本の書式を理解**：和暦、元号リスト「昭和・平成」、（満　歳）、期間の「～」と（　日間）、〒・電話・時刻、□チェック、「男 ・ 女」、1文字1マス、ふりがな、明細表
- **AIから使える**：MCPサーバーとClaude Codeスキルを同梱しています
- **ブラウザ版**：1ファイル、外部通信なし、オフラインで動きます

### 「壊さない」をどう確かめたか

ここがいちばん手間をかけた部分です。

- 本物のExcelで保存したファイルに書き込み、Excel（COM経由）で開いて、修復ダイアログが出ないことを確認しました
- 「Excelが修復を求める」「値が黙って消える」ケースを探し、実機で再現した14件を潰しました。新しい行の順序、範囲外のセル番地（A0 はExcelごと落ちます）、NaN、32,767文字の上限、テーブル見出し、配列数式、結合セルの隠れた部分、`_x0031_` のエスケープなどです
- 書き込み後には構造の自己チェックと読み戻しをし、どちらかが通らなければファイルを残しません

### 技術的なポイント

- ElementTree で保存し直すと名前空間の接頭辞が変わり、`mc:Ignorable` との対応が崩れてExcelが「壊れている」と判定します。そのため、書き込みは**文字列の手術**で行っています
- 新しいセルには、行や列の既定スタイルを引き継がせます。方眼紙はシート全体にフォントを設定していることが多いからです
- MCPサーバーは改行区切りのJSON-RPCを自前で実装しました（約210行）

### 使い方（Claude Code）

フォルダを開くと、スキルとMCPサーバーが有効になります。あとは「この出張申請書を埋めて。12月1日〜3日に大阪、…」と頼むだけです。

## 想定する反応への回答

- **Q. Copilot in Excel でよくない？** → ローカル完結・無料で、エージェント（Claude Code や MCPクライアント）から呼べるのが違いです
