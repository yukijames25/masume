役所や社内の申請書には、いまも「Excel方眼紙」で作られたものがたくさんあります。列幅を細かくそろえ、セルを結合して罫線を引いた、あの様式です。

「この申請書、埋めといて」とAIに頼めたら楽なのに、実際にやらせるとうまくいきません。そこで、**様式を一切加工せずに、AIエージェントが読み書きできるようにするツール** masume（升目）を作りました。

https://github.com/yukijames25/masume

## なぜAIは方眼紙が苦手なのか

AIに方眼紙を**読ませる**ツール（MarkItDown など）は増えました。でも**書かせる**となると別の難しさがあります。

- **どこに書けばいいか分からない**：汎用のExcel操作ツールはセル番地で書きます。方眼紙では「氏名の欄」が `H9:AG9` を結合した枠だったりするので、AIが番地を外します
- **保存し直すと壊れる**：ライブラリで読み込んで保存し直すと、図形・印影・一部の書式が落ちることがあります。提出する様式でこれは致命的です
- **日本の様式の書き方**：「令和　年　月　日」「□有　□無」「〒　　－」「男 ・ 女」を丸で囲む、1マス1文字……。これを扱うツールが見当たりませんでした

## できること

架空の休暇届で試すとこうなります。まず、入力欄を見つけます。

```
$ masume inspect 休暇届.xlsx

10 fields
休暇届!T5:AG5       日付(セル内)    [休暇届] 日付
休暇届!H8:S8        テキスト       [申請者] 所属
休暇届!X8:AG8       テキスト       [申請者] 社員番号
休暇届!H9:AG9       テキスト       [申請者] 氏名
休暇届!H12:AG12     選択         [休暇内容] 休暇の種類  選択肢=年次有給休暇/特別休暇/代休/その他
休暇届!H13:P13      日付         [休暇内容] 開始日
休暇届!U13:AG13     日付         [休暇内容] 終了日
休暇届!H14:K14      テキスト       [休暇内容] 日数
休暇届!B16:AG19     テキスト       [休暇内容] 理由
休暇届!B21:AG21     テキスト(セル内)  [休暇内容] 備考
```

テンプレートに `{{name}}` のような印は不要です。結合セル・罫線・見出しから「ラベル → 入力欄」を推定しています。

値は欄の名前で渡します。日付は西暦のままでかまいません。

```json
{ "日付": "2026-11-19", "所属": "総務部", "氏名": "山田 太郎", "休暇の種類": "年次有給休暇",
  "開始日": "2026-12-01", "理由": "私用のため", "備考": "特になし" }
```

```
$ masume fill 休暇届.xlsx values.json -o 休暇届_記入済.xlsx --brief
{
  "ok": true,
  "saved": true,
  "verified": true,
  "written": {
    "日付": "令和8年11月19日",
    "所属": "総務部",
    "氏名": "山田 太郎",
    "休暇の種類": "■年次有給休暇　□特別休暇　□代休　□その他",
    "開始日": "令和8年12月1日",
    "理由": "私用のため",
    "備考": "備考：特になし"
  },
  "unknown_keys": [],
  "unfilled": ["社員番号", "終了日", "日数"],
  "warnings": [],
  "errors": []
}
```

様式が和暦なら令和に、□は■に、「備考：＿＿＿」は下線を置き換えて書きます。空のまま残った欄（`unfilled`）も返すので、AIは「社員番号は空ですが、よいですか？」と聞き返せます。

書いた結果は、読み直して確かめられます。

```
$ masume md 休暇届_記入済.xlsx --fields fields.json
| id | 種類 | セル | 補足 |
|---|---|---|---|
| 日付 | 日付(セル内) | T5:AG5 | [休暇届] 書式: 令和　　年　　月　　日 現在値: 令和8年11月19日 |
| 休暇の種類 | 選択 | H12:AG12 | [休暇内容] 選択肢: 年次有給休暇 / 特別休暇 / 代休 / その他 現在値: 年次有給休暇 |
| 開始日 | 日付 | H13:P13 | [休暇内容] 現在値: 令和8年12月1日 |
| 終了日 | 日付 | U13:AG13 | [休暇内容] |
（抜粋）
```

ほかに扱える書き方の例です。

- 元号リスト「昭和・平成　年　月　日」、（満　歳）の自動計算、期間「～」と（　日間）
- 〒・電話・時刻の書式（「（　）　－」に `03-1234-5678` を分けて入れる）
- 1マス1文字（法人番号13桁など）、分割欄（「[ ]年[ ]ヶ月」）
- □チェック（1セル内でも別セルでも）、「男 ・ 女」を（女）にする、Excelのチェックボックス（開発タブのもの）
- 明細表（行の追加）、「事項｜変更前｜変更後」の比較表、ふりがな
- 記入例シートの除外、受付印・「※市記入欄」の除外

## 実在の役所の様式で試した

最初は自作の架空様式だけで作っていました。それで一晩作ったあと、広島市が公開している税関係の届出書・申請書6件（.xlsx）で試すと、**自作では出なかった書き方が15種類**出てきました。

- 大きな罫線の枠の中にラベルだけがあり、値はその右の何もないところに書く
- 「所在地」の次の行に「（住所）」がある2行のラベル
- 「令和[ ]年[ ]月[ ]日提出」が別々のセルに分かれている
- 法人番号の13マスが、1文字ずつ結合したセルで描かれている
- チェック欄が、□の文字ではなく、四辺に罫線を引いた小さな結合セル
- 「事項｜変更前｜変更後」の表に、〒・住所・電話の枠が入っている

対応したあと、1ページの届出書・申請書4件で、所在地・名称・法人番号・提出日・担当者・電話・チェック欄・明細表を記入しました。Excelで開いてPDFに出力し、すべて正しい枠に入っていることを目で確かめています。2行1組の大きな異動届と、数値の明細書は、まだ人の手直しが必要です。

（様式ファイルは再配布の可否を確認していないので、リポジトリには入れていません。テスト用の様式はすべて自作の架空のものです。）

## 「利用者役のAI」に使わせて直した

テストが全部通っても、使う人が詰まるかどうかは分かりません。そこで、**経理担当者役のエージェント**に、上司の口頭の依頼文だけを渡して、実在の様式2枚を埋めさせました。詰まった所を直して、同じ依頼で測り直しています。

| 指標 | 2回目 | 3回目 |
|---|---|---|
| 正しい欄に入った事実 | 19/19 | 20/20 |
| 回避策（セル番地で直接書く）が必要だった事実 | 3 | 0 |
| 黙って誤った値を書いた | 1 | 0 |
| 迷った・推測した点 | 12 | 9 |

いちばん怖かったのは、2回目で見つかった「黙って誤った値を書く」ケースです。年月の欄（「令和[ ]年[ ]月」）に `"2026-12"` を渡すと、**「令和2026年」と書かれ、エラーも警告も出ませんでした**。そのまま提出すれば誤った届出です。今は `"2026-12"` `"令和8年12月"` `"R8.12"` のどれでも令和8年になり、西暦の年がそのまま入る形はエラーにしています。

ほかにも、使わせて初めて分かったことがありました。

- 確認画面で、□が空でも「選択済み」と表示されていた（`"" in "■☑"` が True になるという、古い不具合）
- 狭いセルに電話番号の「251」を数値で書くと、Excelでは `####` と表示される
- 長い住所が枠の外にはみ出し、一部が3ページ目に印刷されていた → 列幅・文字サイズ・縮小設定から見積もって warning を出すようにした

## 壊さないための工夫

- **書き込みは文字列の手術**：ElementTree で保存し直すと名前空間の接頭辞が変わり、`mc:Ignorable` との対応が崩れて、Excelが「修復が必要」と判定します。そこで、シートXMLの該当セルだけを文字列として差し替えています。ほかの部品はバイト単位で同一です
- **Excelが嫌うものを先に断る**：範囲外のセル番地、NaN、32,767文字超、テーブルの見出し行、配列数式の範囲、結合セルの隠れた部分などは書き込まずにエラーにします。Excelで実際に再現した14件を潰しました
- **書いたら読み直す**：保存後に読み戻して確かめ、一致しなければファイルを残しません
- 新しいセルには、行や列の既定スタイル（フォントなど）を引き継がせます

Python標準ライブラリだけで動き（依存ゼロ・本体約110KB）、MCPサーバーも改行区切りのJSON-RPCを自前で実装しています。

## 使い方

```bash
pip install git+https://github.com/yukijames25/masume
masume md 様式.xlsx                       # 入力欄の一覧とレイアウト（AIに読ませる用）
masume inspect 様式.xlsx --json > fields.json
masume template 様式.xlsx > values.json   # 値がすべて null の雛形
masume fill 様式.xlsx values.json -o 記入済.xlsx --brief
masume md 記入済.xlsx --fields fields.json  # 記入後の確認
```

**Claude Code から使う**

```bash
claude mcp add masume -- masume-mcp
```

ツールは `inspect_form` / `form_to_markdown` / `fill_form` / `list_sheets` の4つです。リポジトリの `.claude/skills/masume/` にはスキル（手順書）も入っています。値の渡し方や、聞いていない事実は推測せずユーザーに確認すること、などを書いてあります。`~/.claude/skills/` にコピーすれば、どのプロジェクトでも使えます。

**ブラウザ版（インストール不要）**

`web/index.html` をダウンロードして開くだけで使えます。1ファイルで、ページ自体が外部への通信を禁止しているので、社外秘の様式も端末の外に出ません。中身はPython版と同じロジックで、2,000項目あまりのチェックで出力が一致することを確かめています。

## できないこと

- **PDFの様式**：広島市の税関係のページを数えると、様式の約7割はPDFでした。masume が扱えるのは、Excelで配られている残りの約4分の1です
- 大きな様式（2人分を縦に並べた異動届など）や数値の明細書は、`inspect --json` の結果を人が直して `--fields` で使う運用が必要です
- 検出は経験則なので、外れることがあります。外れた欄は `"C12": "..."` のようにセル番地でも書けます
- `.xls`（旧形式）は `masume convert` で変換してから使います（Excel か LibreOffice が必要）

## おわりに

まだ実際の利用者がいません。お手元の申請書で試して、外れた欄やずれた記入があれば [Issue](https://github.com/yukijames25/masume/issues) で教えてもらえるとうれしいです。様式そのものを添付できない場合は、記入前の様式で `masume md 様式.xlsx` を実行した出力を貼ってもらえると助かります。
